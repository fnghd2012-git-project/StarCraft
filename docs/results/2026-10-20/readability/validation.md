# 2026-10-20 클래스 구조·가독성 변경 검증

목적은 코드 추적을 쉽게 만드는 것이다. 게임 규칙·패킷 형식·워커 설정의 동작을 유지하면서 선언과 구현을 정리했다.
성능 비교나 1,500명 시연을 새로 측정한 작업은 아니다. PDF의 해당 수치는 `2026-10-19/iocp/` 측정 기록을 보존한다.

## 바꾼 구조

- `IocpServer::Impl`을 제거하고 멤버·private 함수 선언을 `IocpServer.h`에 배치했다. 구현은 `IocpServer.cpp`의 `IocpServer::함수명`으로 찾는다.
- 연결 상태를 `IocpSession.h`로 분리했다. 소켓·버퍼·세션별 잠금의 소유 관계를 주석으로 표시했다.
- `.cpp` 안에 숨어 있던 `NetworkWorker`, 더미 `BattleWorker`, `ReplayWindow`, `OdbcStatement`를 헤더 선언과 cpp 구현으로 나눴다.
- `IoBufferPool`의 함수 본문을 cpp로 옮겼다. `GameLogic.h`는 관련 함수끼리 묶고 설명을 달았다.
- 자체 작성 C++ 파일의 조건문·반복문·함수를 여러 줄로 펼치고 서식을 통일했다. 생성된 Protobuf와 외부 라이브러리는 대상에서 제외했다.

## 재실행 결과

실행 상세와 시간은 `regression.json`, 표의 각 항목은 같은 폴더의 `.log`에 보관한다.

| 검사 | 결과 |
| --- | --- |
| x64 Debug / Release 빌드 및 기본 검사 | 통과 |
| Debug IOCP / WSAPoll 통신·프레임 검사 | 양쪽 통과 |
| 전투 워커 1 / 2 / 4 고정 입력 및 통합 검사 | 통과 |
| WSAPoll 게임 통합 | 통과 |
| 접속 정원·자동 전투·일반/월드 채팅 | 통과 |
| 계정·세션 복구 | 통과 |
| Redis 랭킹·장애 복구·최종 결과 | 통과 |
| 리플레이 라이브 상태 대조·변조/잘림 거부·오프라인 제어 | 통과 |
| IOCP 재접속·RST·느린 수신·종료 | 통과 |
| 풀 OFF / ON / 작은 풀의 고갈 후 회복 | 통과 |

`iocp-fault.json`의 세 조건 모두 종료 후 `pending_io=0`, `pool_in_use=0`을 확인했다.
작은 풀 조건에서는 `pool_exhausted=16`을 발생시키고 연결 정리와 재접속을 검사했다.
풀 ON/OFF 결과의 할당·재사용 수는 이번 회귀에서 관찰한 값이며 처리량 비교 수치가 아니다.

테스트는 별도 실행 사본과 테스트 DB Realm을 사용했다. 기존 `Server.ini` 및 과거 성능 결과 파일을 덮어쓰지 않았다.
회귀 스크립트: `run_regression.py`. 재실행 시 `--resume`은 통과한 항목을 건너뛴다.
